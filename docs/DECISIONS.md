## D-019 — قفل رزرو با reservation_locks
- **تاریخ:** 2026-11-02
- **وضعیت:** confirmed برای موتور فعلی
- **تصمیم:** رزرو داخل یک transaction است. منابع به ترتیب نوع و شناسه قفل می‌شوند. ردیف `reservation_locks` upsert می‌شود و `lock_version` افزایش می‌یابد، سپس `lockForUpdate` روی همان ردیف و ردیف دامنه اجرا می‌شود. SQLite عبارت `FOR UPDATE` را حذف می‌کند، پس افزایش نسخه همان write lock است. خطای busy تا چهار بار تکرار و بعد به «این بازه همین الان رزرو شد.» تبدیل می‌شود.
- **دلیل:** قفل allocation موجود دو insert هم‌زمان در بازه خالی را نمی‌بندد. تست دو فرایندی روی فایل SQLite فقط یک برنده دارد. این تست gap lock اینودبی را اثبات نمی‌کند.

## D-024 — نوبت داخلی پذیرش، اقدام مجاز است
