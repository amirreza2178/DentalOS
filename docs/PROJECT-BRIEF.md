# خلاصه پروژه DentalOS

**نام کاری:** DentalOS  
**نوع:** سیستم مدیریت کلینیک دندان‌پزشکی / ارتودنسی  
**محدوده اولیه:** یک کلینیک  
**افق معماری:** قابلیت گسترش به چند کلینیک بدون multi-tenancy زودهنگام  
**پنجره تحویل MVP:** حدود ۸ روز کاری  
**تاریخ شروع مأموریت Day 1:** 2026-11-02

---

## مسئله کسب‌وکار

یک کلینیک ارتودنسی باید نوبت‌دهی، پذیرش، صف انتظار، برنامه‌های درمانی، تخصیص منابع (صندلی/یونیت، متخصص، کادر بالینی)، پیگیری بیمار، و ثبت هزینه/پرداخت را به‌صورت هم‌زمان و قابل‌اتکا مدیریت کند. دو پذیرشگر هم‌زمان کار می‌کنند؛ بیماران می‌توانند آنلاین نوبت بگیرند؛ متخصص طرح درمان می‌دهد و کادر بالینی وظایف را اجرا می‌کنند.

## هدف محصول

ساخت MVP قابل‌استفاده در عملیات روزانه پذیرش با قواعد زمان‌بندی سخت‌گیرانه، کنترل دسترسی مبتنی بر نقش، رابط فارسی RTL، و تاریخ جلالی در نمایش — بدون تشخیص/تجویز خودکار توسط نرم‌افزار.

## اولویت‌های محصول (به ترتیب)

1. تجربه پذیرشگر (تقویم، جستجوی بیمار، رزرو سریع، چک‌این، صف انتظار، وضعیت‌ها، نوبت بعدی)
2. زمان‌بندی قابل‌اتکا (در دسترس‌بودن منابع، شیفت، تعطیلات، جلوگیری از تداخل)
3. پرتال بیمار (ثبت‌نام، ورود، اسلات‌ها، رزرو، تاریخچه نوبت)
4. CRM بیمار و تاریخچه ویزیت
5. صف انتظار و گردش پذیرش
6. صورتحساب پایه، پرداخت حضوری، مانده حساب
7. گزارش‌ها و audit در حد نیاز MVP

## بازیگران اصلی

| نقش | توضیح کوتاه |
|-----|-------------|
| Receptionist | پذیرش و عملیات روزانه نوبت/صف/پرداخت |
| Specialist (Orthodontist) | معاینه، طرح درمان، تخصیص وظایف بالینی |
| ClinicalStaff | اجرای وظایف تخصیص‌یافته تحت نظارت حرفه‌ای کلینیک |
| Patient | ثبت‌نام، رزرو آنلاین، مشاهده تاریخچه خود |
| ClinicAdmin | تنظیمات کلینیک، منابع، شیفت‌ها، سیاست‌ها، کاربران |

> **فرض موقت (برچسب‌خورده):** نقش ClinicAdmin در روز اول برای مدیریت تنظیمات لازم فرض شده؛ ممکن است همان متخصص یا پذیرش ارشد باشد. تأیید با کلینیک لازم است.

## تمایز مفاهیم دامنه (غیرقابل ادغام)

- **Appointment:** رزرو زمانی روی منابع
- **PatientVisit:** حضور واقعی بیمار در یک نوبت/روز
- **TreatmentPlan / TreatmentTask:** برنامه و کارهای بالینی
- **WaitingQueueEntry:** وضعیت صف انتظار در پذیرش

## محدودیت‌های صریح فناوری

- Laravel 13 + PHP 8.3+ + Blade + Tailwind + Vite
- MariaDB هدف تولید/توسعه اپ؛ تست با SQLite in-memory
- Alpine.js فقط در صورت نیاز واقعی UI
- بدون microservice، بدون repository اجباری، بدون React/Vue زودهنگام
- منطق کسب‌وکار خارج از Controller (Form Request، Policy، Service/Action متمرکز)
